## Codebase Patterns
- Build uses `tsup` with multi-config array in `tsup.config.ts` (ESM, CJS, IIFE browser bundles)
- Post-build script `scripts/post-build.js` creates `dist/browser.zip` using system `zip` command
- `wampy-cra.js` uses top-level `await import('node:crypto')` — incompatible with CJS format, so CJS build emits it as `.mjs`
- Typecheck script uses `--declaration false --declarationMap false` flags with `--noEmit` to avoid TS9005 errors from JS test files
- `checkJs: false` in tsconfig.json — JS files are included for module resolution but not type-checked
- External deps for library builds: cbor-x, msgpackr, tweetnacl, websocket, ws, yargs, color-json, node:crypto
- Browser IIFE bundles use `noExternal: [/.*/]` to bundle all dependencies inline
- When renaming `.js` → `.ts`: import paths in consuming files stay as `.js` (NodeNext resolution), but `tsup.config.ts` entry paths must be updated to `.ts`
- For globalThis augmentations (e.g., `MozWebSocket`), use `declare global { var ... }` — NOT `declare const globalThis: typeof globalThis & { ... }` (causes circular ref)
- Serializer interface defined in `src/serializers/serializer.ts` — all serializers implement it; import as `import type { Serializer } from './serializer.js'`
- When third-party types are incomplete (e.g., cbor-x missing `int64AsNumber`), extend the interface locally rather than using `@ts-ignore`
- `node:crypto` SubtleCrypto and DOM SubtleCrypto types are incompatible — extract `subtle` property directly and type-assert to `SubtleCrypto` to unify both environments
- `tweetnacl` ships its own `.d.ts` — no `@types/tweetnacl` needed
- Core Wampy types are in `src/types.ts` — import with `import type { ... } from './types.js'`
- `Deferred<T>` is in `src/utils.ts` — used by cache (connectPromise, closePromise) and internal requests/calls
- `WampyCache.timer` is typed as `ReturnType<typeof setTimeout> | null` for cross-environment compatibility
- Internal `_requests` map uses `WampRequest` type; `_calls` map uses `WampCall` type (extends Deferred with optional `onProgress`)
- Subscribe/Register request callbacks extend `Deferred` with additional properties (`onEvent` for subscribe, `rpc` for register)
- `Deferred<T>` is contravariant on `onSuccess` — when storing typed Deferreds in `WampRequest.callbacks` (which expects `Deferred<unknown>`), cast via `as unknown as Deferred`
- `SUCCESS` constant from constants.ts lacks `reqId` — use `{ ...SUCCESS, reqId: 0 }` when assigning to `WampyOpStatus`
- When passing `this._options` to `getWebSocket()`, cast as `Record<string, unknown>` to avoid `null` vs `undefined` incompatibility on `ws` property
- `_isPlainObject` is typed as a type guard: `input is Record<string, unknown>` — this narrows types in conditional blocks
- CLI files (`cmd/`) are NOT built by tsup — they run from source. `bin` entry in package.json points to `cmd/cli.js`
- yargs `MiddlewareFunction` expects `void` return — middleware callbacks that mutate `argv` should NOT return the argv object
- Auth plugin `sign()` returns functions with specific info types (`WampCraInfo`, `CryptosignInfo`) — cast to `AuthPlugin` when assigning to `authPlugins`
- `ws` module needs `@types/ws` for TypeScript; `yargs` needs `@types/yargs`
- yargs `CommandModule` handler must accept `Arguments` — cast to specific argv interface inside the handler body, not in the parameter type
- CLI command interfaces extend `CliArgv` (from `wampy-helpers.ts`) with command-specific options (positionals, flags)
- Test fake WS files use function-constructor pattern — type with a `FakeWebSocket` interface and cast `function() {} as unknown as FakeWebSocketConstructor`
- `WAMP_MSG_SPEC` is `as const` — its values are literal types. When using `.includes()`, cast the array to `number[]` (e.g., `([WAMP_MSG_SPEC.CALL, ...] as number[]).includes(value)`)
- `send-data.ts` exports `SendDataItem` interface for typing the mock server response data
- `@types/mocha`, `@types/chai`, `@types/sinon` are added as devDependencies for test file typing
